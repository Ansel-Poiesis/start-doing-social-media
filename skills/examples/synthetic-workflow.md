# 六阶段交接演示：给同事演示表格整理

性质：**synthetic / 合成教学**。以下人物、材料、反馈和数值仅用于展示交接方式，不是项目实测、平台规则或真实运营案例。没有执行发布、抓取或付费调用。

## 1. creator-profile → profile-v1

假设输入：“每周能花两小时，把办公小问题讲清楚；不露脸、不晒同事数据。”

记录为自述 M 和意愿 D。供给能力证据未知；拟议观众是偶尔处理表格的同事，仍属假设 H。输出 profile-v1，状态 draft，未获得真人确认。平台选择暂不生效。

## 2. platform-research → research-v1

当前决定：录一段演示是否比长文更易理解。平台候选暂不确定。claim R1“该平台允许某种商业导流”为未知，未查询官方原文，因此不得据此安排商业引导。

可继续准备不含私人数据的素材和试读问题；平台费率、推荐、首发与 AI 标识全部留在待核清单。research-v1 状态 needs-evidence，不生成“最适合某平台”的结论。

## 3. topic-planning → topic-v1

候选 A：演示把一列混合格式日期整理一致；候选 B：列出多个快捷键。假设选择 A 用于教学演示，理由是承诺和结果更容易观察，**不是获得真人方向确认**。

主要目标：看完能解释两个操作步骤。信号是试读后复述和实际完成情况，不套用评论率。事前计划：用脱敏示例表，记录哪些步骤被误解；不预填真实反馈。

## 4. production-brief → production-v1

结构：展示错误 → 演示一例 → 解释适用条件 → 给观众练习。素材为自行构造的示例表；不得录入同事文件。保留软件版本和操作复现待核项。

验收：画面中每一步清楚；结论与演示一致；不能恢复的错误有说明。没有实际完成视频，成品字段留空；状态 needs-evidence，不能进入成品签收。

## 5. publication-review → review-v1

成品缺失、目标平台未定、现行规则未核，三项均 blocked/unknown。输出结果 blocked；不执行发布，不产生 URL，不把本例标为 published。

此阶段展示上游缺口如何阻止外发：模板可以填完，发布条件仍未满足。

## 6. content-retrospective → retrospective-v1

输入中没有真实回执或后台指标，因此所有结果字段为未知。不能把零播放当事实，也不能用想象中的“同事看懂了”验证方法。

仅示范下一轮计划：完成真实演示后，在参与者授权下记录复述与操作困难，再决定是否改步骤顺序。真实数据到来前，结论保持“无法判断”。

## 验证范围

本例证明六份模板能传递版本、证据状态与阻断，不证明六个技能在真实创作中有效。真实试答、贯穿案例、平台账号内规则核验仍需独立完成。
