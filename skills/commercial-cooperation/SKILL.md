# 可选商业合作

## 输入

- 创作者是否选择参与、目标、可拒绝/暂停的边界和适用主体。
- 合作方主体、委托授权、产品/服务、受众、支持材料、期望用途与涉及地区。
- 拟交付件、时间、验收人/标准、修订范围、取消条件和各方责任。
- 作品及素材权利、自然发布/转发/付费投放/再授权等拟用范围。
- 目标平台、入口、账号类型与当前披露规则；拟议成本、收款节点和凭据要求。

商业合作不是创作的默认目标。必要材料缺失时保留 unknown，不推定合作方授权、产品事实或创作者同意。

## 按需读取

从仓库根目录运行：

    node scripts/read-article.mjs commercial

详读[商业合作与项目核算协议](../../docs/agent-knowledge/08-commercial-cooperation.md)。平台披露、素材权利和最终成品由[publication-review](../publication-review/SKILL.md)逐目标检查。作品有真实发布回执后，实际效果与到账记录再分别交 content-retrospective；不得把计划金额作为收入。

## 工作步骤

1. 先记录“参与 / 拒绝 / 暂缓 / 不适用”及本人确认范围；未选择商业目标且无主动邀约时，本流程可以不启动。
2. 筛查合作方主体与委托权限、产品主张支持材料、目标受众、涉及地区、风险类别和平台。对方要求伪造体验/效果/数据、隐瞒必要披露、越权使用素材或提供账号凭据时，建议拒绝或暂停并说明具体原因。
3. 把每个交付件、格式、时间点、验收人和通过标准写明；限定修订轮次、新增需求、补拍、延期和取消如何处理。不用“满意为止”等无法判定的条件替代验收标准。
4. 按用途拆分完成作品的使用权：自然发布、品牌转发、付费广告、账号授权广告、剪辑再利用、其他平台/渠道、地区、期限、独家与下架。未知或未明确许可的用途保持关闭。
5. 对每个目标平台/地区/入口查当前官方披露规则，记录 URL、查阅日、适用条件和账号内可见状态；让 publication-review 复核事实、素材与披露。不能用单一法域或平台示例代替具体判断。
6. 建立估算、提出价、双方确认金额、应收、实际到账、退款、第三方费用、平台费用、税费、工时和凭据等分栏。只有真实凭据支持的实际收支才标为已发生；保护账务与身份隐私。
7. 将拒绝理由、未知项、负责人、允许的下一动作和停止条件记入[合作记录模板](assets/template.md)，由本人或有权限的专业人士确认后再交接。

## 输出与交接

输出一张可复核的合作筛查与范围记录，含逐项交付/验收、修订边界、使用权、披露来源/日期、估算与实际分栏及凭据状态。需要成品审阅时交 publication-review。真实合同、报价、发票、账户数据和收款凭据保存在用户指定的私人目录，不进入公共仓库。

## 停止条件

创作者未主动选择时不得假定其接受商业化。合作主体权限、产品主张、素材权利、披露条件或关键验收条款不清时暂停受影响的谈判/交付；要求虚假陈述、非法规避、超范围使用或敏感凭据时拒绝并交本人判断。不能提供通用市场报价、收入保证、法律/税务/会计意见，也不代表本人签约、报价、收款、发布或作出承诺。
