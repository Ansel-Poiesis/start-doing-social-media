# 跨平台版本适配

## 输入

- 母稿及素材的稳定 ID、版本、来源、事实、承诺和不得删去的限定。
- 创作者选定的平台、具体入口、地区、账号条件、用途和拟定时间。
- 文本、图片、音频、视频、字体、肖像、商标及引用各自的权利人和许可材料。
- 负责改编、复核和批准的人，以及可以接受的未知和延期范围。

权利材料或目标入口缺失时，先记录未知；公开可见、平台内可用或曾经获准一次使用，不自动意味着跨平台或商业复用许可。

## 按需读取

从仓库根目录运行：

    node scripts/read-article.mjs distribution

详读[跨平台版本适配协议](../../docs/agent-knowledge/07-cross-platform-adaptation.md)。对每个准备外发的版本，另行执行[publication-review](../publication-review/SKILL.md)；发布后的数据观察转交[content-retrospective](../content-retrospective/SKILL.md)。不能以本工作流代替事实、权利或当前平台规则核验。

## 工作步骤

1. 冻结母稿 ID、版本和读取日期，列出核心承诺、事实及出处、必须保留的限定、可改部分和禁止用途。
2. 为每个候选平台/入口创建独立派生版本和父子关系，记录目标观众任务、改动内容与理由。未选择的目标标为候选或不适用，不生成假发布状态。
3. 对每项素材逐条登记来源、权利人、许可凭据、署名、平台/入口、地区、期限、自然发布、商业使用、付费推广、再授权和剪辑范围。许可未覆盖的用途保持 blocked/unknown。
4. 对每个版本查目标地区和入口的当前官方原文，包括格式、重复内容、音乐、链接、商业与 AI 标识等适用条件。记录 URL、原文发布日期（可得时）、查阅日、适用对象和账号内可见状态；不从搜索摘要或其他平台外推。
5. 对照母稿逐段复核事实和限定，标出删改及其影响。每个版本分别填写审核人、审核状态、审批记录、实际发布状态和可核回执；没有回执就不能写 published/scheduled。
6. 把状态为 blocked/unknown 的关键权利或规则列入阻断项，暂停受影响版本。其余可在内部继续制作，但先交 publication-review 获取逐平台审阅结论。
7. 将母稿、派生版本、素材授权、规则来源、审批与回执分别写入[版本矩阵模板](assets/template.md)，各平台数据与指标留作独立记录。

## 输出与交接

交付一份母稿—派生稿关系图、逐平台版本矩阵、逐资产权利表、规则来源与核验日期、审批/回执状态及阻断清单。交 publication-review 逐版本检查。若已经有经核实的发布回执，再将对应版本交 content-retrospective；不合并不同平台口径。

真实作品、授权文件、账号状态和后台导出只能保存在用户指定的私人目录，不提交至公共仓库或教学案例。

## 停止条件

素材权利、用途范围、目标入口或关键规则不清时，将受影响派生版本标记 blocked/unknown 并暂停外发。任何版本尚未逐平台检查时，不标为可发布。此 skill 不登录账号、不调用平台 API、不上传素材、不自动改编后分发、不安排或执行发布，也不承诺触达、流量或增长。
