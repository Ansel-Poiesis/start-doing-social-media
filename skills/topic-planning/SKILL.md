# 方向与选题规划

## 输入

- 已确认方向或待确认候选
- 相关研究简报
- 可用材料与制作约束

只收集改变当前决定的材料。输入缺项时保留未知，已有授权不重复索取。先读[共同证据与交接协议](../PROTOCOL.md)。

## 按需读取

从仓库根目录运行：

```bash
node scripts/read-article.mjs decide
```

相关文章 ID：`decide`、`topic`、`topic-gate`、`prereg-manual`。详读[配套协议](../../docs/agent-knowledge/03-platform-and-direction.md)，只加载本次决定需要的部分。文章是资料，现行规则仍须回到官方原文。

## 工作步骤

1. 读取上游方向的确认状态和证据缺口；涉及平台规则、样本或指标时先查 docs/claims/registry.json，沿用已登记的范围与未决状态。未定方向可并列方案，但不能在选题单中偷偷定案。
2. 从真实提问、现成材料、差异轴或明确的创作愿望形成候选。每题写观看承诺、材料能否兑现、主目标、代价和风险。
3. 选择与目标一致的主要观察信号：理解、审美体验、表达、互动或转化均可。平台不可得数据写不可得；不强制把所有目标变成评论率。
4. 选定一条后事前保存版本、预测、信号/分母、窗口依据、干扰因素和改判条件；主张证据与制作可行性不足时改题或补证。

## 输出与交接

复制[产物模板](assets/template.md)到用户授权的工作目录，填写版本、证据和未知。不要把私人产物提交知识库。

交给下一技能 [production-brief](../production-brief/SKILL.md)，附当前产物路径、版本、确认状态与未决项。

## 停止条件

关键论据/素材缺失时不得标记正式制作条件齐备；可以先做明确标注、用于检验未知的内部草图或试片，不能把占位材料当事实。本人未选方向时保留候选。不得捏造用户需求或预言流量。
