# 账号运营

## 输入

- 创作者本人选择的目标、非目标、公开范围和可接受的时间/金钱/精力上限。
- 内容队列、现有产物 ID 与版本、当前进度、依赖、负责人和协作者。
- 评论处理偏好、隐私要求、可能需要升级的安全情形。
- 若涉及平台功能，提供目标平台、产品入口、地区、账号条件和当前一手规则；缺少时标为未知。

没有本人确认的目标时，不替本人设定增长、变现或更新频率。不要索要密码、验证码或不必要的后台数据。

## 按需读取

从仓库根目录运行：

    node scripts/read-article.mjs operations

详读[账号运营与社群边界协议](../../docs/agent-knowledge/06-account-operations.md)。涉及制作、发布审核或回看时，再读[production-brief](../production-brief/SKILL.md)、[publication-review](../publication-review/SKILL.md)或[content-retrospective](../content-retrospective/SKILL.md)；不要重复复制那些检查。来源规则以目标平台当前官方原文为准。

## 工作步骤

1. 将目标、非目标、期间、容量和允许投入分别记录为本人确认或待确认。时间不足以形成计划时先询问最小必要问题，保留未确认状态。
2. 把事项按来源和工作状态分列，至少记录内容 ID/版本、下一动作、负责人、依赖、估算工时/成本与检查点。排期使用创作者提供的容量；没有真实记录时标成估算，不把估算当实际产能。
3. 给计划保留缩小、顺延、取消和暂停的出口。安排多人接力时，逐人列出获准读取、编辑、审批或代表账号行动的范围；默认不授予发布、删评、公开回复或商业承诺权限。
4. 将评论分为事实问题/纠错、普通反馈、隐私请求、骚扰或威胁、垃圾/引流及其他。为每类记录是否答复、由谁审阅、是否升级、允许的下一动作；不要求逐条回复，也不复制敏感原话到公开示例。
5. 对涉及账号界面、安全、未成年人、法律争议或可信威胁的事项标出未知与人工升级路径。平台功能须核目标账号当下可见的入口；不能用一个平台的功能推断其他平台。
6. 周期回看只比较计划与实际投入、完成/延期/取消及创作者说明。将观测与解释分开，不从单次表现推导增长因果；必要时把某件作品交给 publication-review 或 content-retrospective。
7. 将完整计划写入[运营计划模板](assets/template.md)，区分估算与实际、草案与本人确认，并把下一负责人和允许的动作写明。

## 输出与交接

输出一份可缩小或暂停的运营计划、协作者权限边界、评论处理表、未知项和回看节点。只在用户指定的工作目录保存真实资料；不要把私人产物提交到知识库。

作品制作交 production-brief；具体成品发布前交 publication-review；已有试读或发布证据时交 content-retrospective。交接时附产物 ID/版本、输入版本、负责人、确认范围、证据、阻断项和允许的下一动作。

## 停止条件

本人未选择目标或容量时，不自行安排节奏。出现隐私泄露、可信威胁、未成年人风险、未获授权的协作者操作或关键平台规则未知时，暂停受影响动作并交由本人或适当专业/平台渠道处理。没有额外授权，不登录账号、不发帖、不回复或管理评论、不作公开承诺、不购买、不调用 API，也不宣称增长结果。
