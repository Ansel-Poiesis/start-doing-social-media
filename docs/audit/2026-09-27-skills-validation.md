# 六个内置技能与开源检查的独立验证

日期：2026-09-27。范围：`skills/manifest.json`、六个 `SKILL.md`、六份模板、共同协议、教学示例，以及正文导出、知识结构检查和公开前扫描脚本。

结论：六阶段能够传递明确标注的输入、版本、证据状态和阻断。发现并修复了正文导出缺少来源/状态、模板交接字段不完整、继承属性被当成文章、扫描器漏扫部分文本和特殊文件名误报。下方是一次实际填写的**合成教学干跑**，不是六位真人的试用，也不证明创作方法或平台适配有效。

## 可复现问题与修复

| 发现 | 复现方式与原结果 | 修复后验证 |
| --- | --- | --- |
| 文章导出丢失建设状态和参考资料列表 | 导出 `profile`，正文结束后没有其 `article.sources` 中的 O*NET、量表研究和许可入口，也没有当前建设状态。 | 导出保留原始状态、来源标题与 URL；正文中的日期原样保留，不虚构缺失的核验日期。检查逐一覆盖全部 49 篇文章。 |
| 无效 ID 可访问对象继承属性 | `node scripts/read-article.mjs constructor` 原来抛出 `TypeError`；网页路由也使用了相同的真假值判断。 | CLI 与网页路由均改为 `Object.hasOwn`。CLI 对 `constructor`、`toString`、`__proto__` 与普通未知 ID 返回用法提示和退出码 1。 |
| 模板缺少统一交接字段 | 按原模板填写 research 等产物，无法在固定位置记录上游版本、当前保存位置、依赖证据和允许的下一动作。 | 六份模板统一加入五项交接元数据，并由 `check-knowledge.mjs` 检查。协议中的方向/发布确认要求保持不变。 |
| 扫描器按扩展名漏扫文本 | 独立 Git fixture 中，同一个假凭据放在 `.md` 被拦，放在 `.txt` 通过。 | 改为扫描可解码 UTF-8 文本，包括 TXT、TOML、PEM 和无扩展名文件。 |
| 部分私钥与私人路径漏报 | 合成 EC 私钥头、Linux 用户目录路径原来通过。 | 扩展私钥头与路径模式；加入 EC/加密 PEM、Windows 盘符、UNC 与 Linux 用户路径用例。 |
| 合法文件名误报、工作树缺失打断扫描 | `doc#draft.md` 被当成 URL 片段；已暂存后从工作树移除的文件报 `ENOENT`。 | 使用原始文件路径读取；先审查 Git 暂存内容，工作树文件缺失时仍完成 index 检查。补充字面 `%` 文件名用例。 |

没有把待修改的根目录文档混入上述扫描器诊断。扫描器测试在独立临时 Git 仓库执行，结束时清理该测试目录；不修改项目暂存区，不打印真实或合成凭据值。

## 触发、依赖和权限检查

- 六个技能各自有明确任务触发、输入、按需读取、工作步骤、输出和停止条件；允许从任意阶段开始，没有要求每次重建档案。
- 完整仓库克隆是运行前提；单独复制一份技能会丢失共同协议、模板和文章。正文导出只使用 Node.js，不需要账号或模型接口。
- 每阶段能读取其模板、配套协议和有效文章 ID。新增检查拒绝指向仓库之外的依赖路径，并核对 manifest 版本、schema、名称、输入输出与下游名称。
- `publication-review` 明确不执行发布；`owner-confirmed` 必须来自真实确认。素材权利、规则或账号资格未知时，填写完模板不等于可以外发。
- 私人档案和后台数据不进入 Git；共同协议要求对网页/附件中的指令保持数据边界。以下场景完全使用合成材料。

本轮只为测试协议构造以下素材，不查询真实账号、不确认任何当前平台规则，也不安排发布：

## S1 创作者档案：实际输出

按 `creator-profile` 读取档案文章、题库与配套协议，只整理给定内容，没有编造二十题的真实回答。

| 字段 / 证据 ID | 记录 | 来路与未知 |
| --- | --- | --- |
| 目标 SYN-P01 | 想把位置记录方法讲清楚 | 来自合成输入；成功判据待真人确认 |
| 供给 SYN-P02 | 自述喜欢整理资料 | M；没有作品、重复实践或他人反馈证据 |
| 表达 SYN-P03 | 不露脸，可先提议文字卡片 | 不露脸为 D；接受文字形式仍为 H |
| 观众 SYN-P04 | 找书困难的租房学生 | H；没有真实需求调查 |
| 产能/边界 SYN-P05 | 每周两小时；不拍家人、不暴露住址 | 合成 M/D；不得推成永久人设 |

候选模式：“愿意整理并解释具体信息”，仅为 I。反例：喜欢整理自己的东西，不代表愿意长期拍摄或教别人。最小试作提案：先做一张只使用虚构书名的位置卡。

三个关键未知：实际表达意愿、可展示作品、目标观众是否需要此方法。交给 S2 的仅为上述五个字段及证据 ID；不标记方向生效。

## S3 方向与选题：实际输出

候选 A：“三列位置卡：书名、书架、层号”；候选 B：“整理书架的一整套流程”。教学分支选 A，因为现有 SYN-DATA-01 能完整展示它；B 涉及未提供的整理过程。此选择是 SYN-CHOICE-01，不是创作者本人签字。

选题卡的观看承诺：“看完能按示例说出乙书放在哪，并知道位置变更后该改哪一格。”主目标是理解，不是播放量或评论率。核心材料仅为 SYN-DATA-01，不能据此声称这种方法适合所有人或能节省多少时间。

预注册草案 `SYN-PRED-v1`：在一次内部试读后，逐人记录是否能解释 A2 的两部分，以及是否会更新搬动后的层号；分母分别保留收到任务数、实际作答数和可判定答案数。观察窗是单次试读结束，不设平台流量窗口。预测方向：“解释 A/B 和数字含义后，答案应能对应示例”，没有旧版或对照就不能判断提升。

成本估计：文字试稿 30 分钟，实际耗时未知。出现真实私人信息或依赖缺失材料时停止。允许 S4 写条件式制作单；真实制作立项仍需本人确认。

## S4 制作简报：实际输出

选择一页文字卡作为本例载体；理由是材料只有三个位置记录，不需要虚构生活镜头。以下就是本轮实际生成的**合成文本试稿 v1**：

> **先别重新整理书架，试着记录书在哪里。**
>
> 这是一张虚构示例卡：甲书在 A1，乙书在 A2，丙书在 B1。A、B 是我们自己给书架起的名字；数字是层号。
>
> 想找乙书，先查“乙书 → A2”，再去 A 书架的第 2 层。把乙书搬走以后，也要更新这条记录；如果卡片没更新，它就可能把你带到旧位置。
>
> 练习：如果乙书搬到 B 书架第 3 层，该把记录改成什么？先用虚构书名试一张卡，再决定自己是否需要它。

结构与证据：首句提出试法；第二段展示 SYN-DATA-01；第三段说明示例的读法及失效条件；末段给可检查任务。不加入未验证的效率数字。

素材账本：只有本报告构造的文字和数据，无真实家庭照片、配乐或外部截图。若改成视频，拍摄、配音、字幕、素材权利、格式与原速视听验收全部仍未执行，不能将本试稿当作已完成视频。

验收条件：读者能区分书架名与层号；能指出搬动后需更新记录；画面不出现真实住址。当前只可核对文本与合成数据一致，真人理解、接受程度和签收仍未知。交给 S5 的是文本 v1，不是一个已认可的发布成品。

## S6 内容复盘：实际输出

为了检验复盘如何处理分母和未知，单独构造 SYN-OBS-01。以下原话和数值**全部是虚构测试记录**，不是参与者反馈：

| 合成记录 | 对“乙书搬到 B 书架第 3 层”的答案 | 可判定性 |
| --- | --- | --- |
| SYN-O1 | “改成 B3，B 是书架，3 是层。” | 可判定，符合本例任务 |
| SYN-O2 | “改成第 3 行，B 是书的类别吗？” | 可判定，混淆含义 |
| SYN-O3 | 无答案 | 缺失；不得补为答错或零分 |

观察：三条 fixture 中两条有答案；两条可判定答案中一条正确。分别保留 `2/3` 和 `1/2` 的分母，不把它们当真实理解率或市场指标。平台曝光、观看、互动、收入与发布回执均为未知。

对照 SYN-PRED-v1：合成记录展示一种可能误解，但没有真人试读、旧版、对照或独立观察，因此无法判断本方法是否有效，更不能推断增长效果。替代解释包括题目措辞、读者已有经验，或者 fixture 作者主动设计了误解；最后一项尤其说明这些记录不能充当效果证据。

下一轮提案：仅将“A/B”改为更明确的“书架 A / 书架 B”，其余文字保持一致；在获准的真实内部试读中保存原始回答、缺失、时间和条件。负责人及参与者未定，因此真实执行仍未开始。不改写经验卡或平台规则；把该提案交回 topic-planning 审阅。

4. 将来源变更传播到正文、配套协议、技能与示例；本次结构检查不替代逐主张的一致性与事实审查。
