# 观察、研究与系统维护：Agent 工作协议

适用的 `article_id`：`evidence`、`iteration`、`competition`、`prereg-manual`、`decision-record`、`constitution`、`hypotheses`、`cards`、五层假设清单、六类经验卡、`mapping`、`governance`、`resources`、`about`。本组工作用于保存和校准判断，不得把一次发布的结果直接改成通用规则。

修订日期：2026-09-27。方法依据来自 `content.js`、`content-research-a/b/c.js` 与 `content-guides.js` 的对应文章。样本、台账和外部资料状态会变化；每次归因必须回到原始记录核对。

## 发布与经验更新

### `iteration`：发布后更新经验

1. 发布前保存版本、预期、目标意图、观测指标、取样时间窗和退出条件（对应 `prereg-manual`）。
2. 发布或试读后先保存可见数据、反馈原文、取数时间和口径；之后才写解释。计数无需分母也可保留；比率缺分母时不自行构造，平台直接显示的比率按原口径注明分母不可得。缺失数据标未知，不补零。
3. 将预期、实际观察、创作者解释和因果假设分栏。比较同类内容时说明差异和不可比处。
4. 根据重复证据提出保留、限域、拆分、修订或退役建议。Agent 只能提案，系统规则变更按 `governance` 流程核准。

### `competition`：让经验彼此竞争

把新旧主张写成可以产生不同预测的候选；为每条列证据等级、适用范围、反例、预期观测和能推翻它的结果。竞争不是投票：同源复述不算多票，缺少辨别性证据时结论为“无法裁决”。形成最小决策记录和新经验卡合同，保留未采用主张及原因。

### `prereg-manual`：预注册

准备检验时，事前记录作品版本、创作者目标、主要问题与辅助观察、定义与来源、窗口依据、基线或无基线说明、判断条件、干扰及负责人。普通创作可用轻量记录；没有预注册的数据标为事后探索，仍可描述现象和生成问题。平台字段按实际权限核可得性，无法取得时寻找能回答原目标的其他观察，不凭空改写本人目标。P75、固定观察时刻和样本数不自动构成成功或有效性门槛。结果追加保存，不回填预测；原问题与进入前/后实际可见元素必须对应。

### `decision-record`：决策留痕

对措辞级和栏目级决定分别记录版本、选择项、依据 ID、冲突证据、责任人、创作者确认、复核日期和撤回/重估条件。修订新增一条记录，禁止覆盖旧判断；若意见不一致，保存分歧而非伪造共识。

## 研究依据与知识资产

### `evidence`：判断材料是否够用

先问当前决定需要哪种材料，再按来源能力分级。官方规则支持规则是什么，不自动证明用户行为或分发效果；研究结论只适用于其样本和时间；内容样本支持被观察到的表达；创作者案例可以支持其可复核的局部事实，并为迁移生成假设，不能直接证明普遍效果；项目推断要写明推理链。每条记录保存出处、日期、方法、适用范围、直接观察、解释、反例和可支持/不可支持的结论。

### `cards` 与经验卡文章

经验卡至少包含 ID、主张、来源类型、具体支持关系、样本/条件、适用边界、反例、待检问题、更新时间和关联假设。历史证据字母标签只是索引，不能替代原文支持范围；规则或来源记录也不必硬编成效果预测。按来源范围读取相应 `article_id`：

- `lib-cross`：跨平台公共模式与大盘锚点；逐平台检查例外。
- `lib-platform`：平台机制卡；回到单平台长文及官方来源核验。
- `lib-academic`：学术机制研究；报告样本、方法和外推限制。
- `lib-benchmark`：行业基准与创作者方法；不得把经验基准写成平台规则。
- `lib-monetize`：变现/收益卡；按账号资格、时间、地区和分母核验。
- `lib-methods`：内容形态方法卡；转成可试的制作动作，不包装成普遍定律。

引用卡时带卡 ID 与状态，不只摘一句结论。卡片互相冲突时并列条件和证据，不取平均。

### `mapping`：研究体系之间的映射与裁决

保留原始分类、规范化后的对应项、映射依据、不可映射项和裁决状态。映射只说明关系，不等于两个体系可互换。对每条裁决指定来源/责任人/缺口；未决项留在登记簿，不由 Agent 擅自合并。

## 体系规则

### `constitution`：使用设计原则与分级检查

先说明创作者目标和当前问题，再选择相关观察；互动只是线索，不与心理动机一一对应。证据、解释和结果分开，栏目、选题、表达按实际决策尺度检查，不强制每次跑完整门禁。适用规则、素材权利和本人底线是硬约束；未验证的技巧、形式和数量阈值不是。方法能帮助回查判断，不保证下一轮流量、收益或质量提高。

### `hypotheses` 与假设层文章

处理假设时按层定位：`hyp-m` 机制、`hyp-c` 栏目、`hyp-t` 选题、`hyp-e` 表达、`hyp-l` 校准规则。引用原假设 ID、版本、状态及其允许用途；检查它是否真的适用于当前平台、账号、观众和内容形态。状态变更说明来源支持、研究或取证设计、样本独立性、偏差与不确定性；不沿用已撤回的固定样本、曝光或天数门槛。个案可改变其范围内的判断或提供反例，不能自动证明跨平台规律。观察与机制因果之间缺少识别证据时，只能记录关联。

### `governance`：修订、限域、拆分或退役

新证据进入时先确认事实源和生效范围；判断旧结论是更新、被反例限域、包含多个机制需拆分，还是已失效应退役。每次变更留旧文、差异、依据 ID、影响到的文章/卡/假设、审阅人和日期。执行防自欺检查：预注册与归因分离、同源去重、未知不补造、时间盒防空转。

### `resources`：处理资料缺口

读取待补清单时先排序“影响当前决定 × 变化速度 × 风险”；明确可由 Agent 检索的公开原文、需要账号权限的信息和必须由创作者提供的材料。无权限处创建任务，不要猜。完成一项后回写来源登记与相关内容版本。

### `about`：守住产品边界

网站是人类学习阅读器，提供概念、文章和来源；不保存创作者档案、不运行 Agent、不替创作者做决定。克隆项目中的 Agent 读取 `docs/agent-knowledge/`、纯题库与本地规则，在用户授权的工作环境中协作。每次任务都清楚说明输入来自哪里，并让创作者确认方向、边界与发布。
