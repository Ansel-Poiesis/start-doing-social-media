# Agent 阅读版：用追问建立创作者档案

## 1. 任务定义

把创作者的目标、经历、可见证据、表达偏好、目标观众、生产条件与边界，整理成一份可供后续创作决策引用、由创作者确认并能随新证据修订的工作档案。

档案回答的是“下一步建议需要知道什么”，不是“这个人本质上是什么类型”。它应帮助回答：

- 哪些创作回报对本人重要，冲突时愿意承担什么代价？
- 他主动投入注意力的对象，是否出现过可复述的真实行动？
- 哪些能力主张有作品、求助、合作、付费或观众反应支撑？
- 哪些创作动作本人愿意反复做，哪些只是喜欢题材但未必喜欢生产过程？
- 哪个具体观众会在什么情境中得到什么？
- 现实时间、资源、隐私和商业边界会排除哪些方案？
- 当前最大未知是什么，哪项低成本试作能获得下一条证据？

## 2. 使用范围与禁止结论

### 适用任务

- 进入账号定位、平台搭配、垂域调研、制作方案或更新节奏判断之前，补齐会改变建议的个人条件。
- 将一段自由回答转成结构化档案草稿，供创作者核对和修订。
- 在作品、资源、目标或生活条件发生变化后，只更新被新证据影响的档案字段。

### 不得生成的结论

- 人格诊断、心理类型、职业适配度、成功概率、必然爆款概率或固定“创作者类型”。
- 单凭自述就断定专业能力、市场需求、观众规模、变现能力或持续创作能力。
- 用 VCTI、MBTI、品牌原型或任一人格分类替创作者确定账号方向。
- 把“当前没证据”写成“没有能力”；把“选择这个选项”写成永久偏好。
- 替创作者选定垂域、平台、商业模式或公开人设。可列候选与代价，决定由本人确认。

若用户只是想讨论、不想建档，先回应其当前问题；不得强迫进入访谈。每个问题都应能说明它可能影响哪类后续决策。与创作判断无关的隐私不收集。

## 3. 证据与状态纪律

每个重要陈述保留原文或可回溯的摘要，并标明以下认识状态：

| 状态 | 含义 | 例子 |
| --- | --- | --- |
| `O` 观察 | 当前可见材料或当场观察到的行为 | 对方展示一段已发布的视频 |
| `F` 可核实事实 | 可由明确来源确认的事实 | 作品发布日期、合作合同中列明的交付 |
| `M` 记忆/自述 | 创作者对自身经历、偏好、目标的陈述 | “我每周会给朋友讲新工具” |
| `I` 推断 | Agent 根据已记录材料提出的解释 | “工具比较可能是稳定供给动作” |
| `H` 假设 | 尚未验证的设想或实验预期 | “初学者可能需要短步骤演示” |
| `D` 立场/愿望 | 本人想维护的价值、目标或边界 | “我不想靠夸大效果换点击” |

这些标签表达陈述的来路，不是可信度分数。一个 `M` 可以是对本人意愿的最直接证据，但不能独自证明外部能力；一个 `F` 也只说明那件事发生，不能自动证明未来可重复。

至少区分五类档案项目：

1. **本人自述**：目标、兴趣、感受、偏好、意愿与边界。
2. **具体事件**：时间、场景、本人采取的动作、投入、结果与复现情况。
3. **外部证据**：作品、长期练习记录、他人反复求助、付费/合作、可归因的观众反馈。
4. **待验证推断**：可能影响方向的模式，并列出它依赖的档案字段。
5. **未知项**：暂缺、矛盾、样本太少或本人尚未决定的部分。

不要混合证据。例如，“我喜欢讲工具”是自述；“过去三个月做了四次工具演示”是具体经历；“两位观众按演示完成了设置”是反馈；“适合做工具教学”仍是推断，需要更多情境和试作验证。

## 4. 访谈顺序与字段

网站的档案正文逐题说明提问理由和虚构示例；题目、提示、理由、示例与选项保存在纯题库 `creator-interview.js`。追问按本协议与 `skills/creator-profile/SKILL.md` 执行；公开项目不依赖旧访谈运行原型。保留字段 ID 和选项 ID；输出给创作者时使用人类可读的标签。默认按以下六组组织：

以下 20 个核心问题是档案字段的边界。外部 Agent 可以在自然对话里调整语气，但不得改变问题所要取得的信息，也不得把两项压成一个结论：

| 顺序 / 字段 | 核心问题 | 主要取得的信息 |
| --- | --- | --- |
| 1 `goals` | 你希望创作给你什么回报？ | 当前最重要的回报，最多两项 |
| 2 `success` | 这件事做成什么样，你会说“成了”？ | 创作者自己的成功判据 |
| 3 `persistence` | 如果连续半年数据平平，什么会支撑你继续？ | 不依赖短期流量的动力或条件 |
| 4 `interests` | 什么事情会让你主动投入注意力？ | 有稳定材料可能的对象 |
| 5 `episode` | 最近一次投入其中的真实经历是什么？ | 时间、动作、投入与结果 |
| 6 `evidence` | 别人为什么会需要你的这部分能力？ | 作品、求助、付费/机会、练习或暂无证据 |
| 7 `monopoly` | 你的职业、经历、爱好里，哪两样交叉起来身边几乎没人重合？ | 个人交叉点；想不到时转问熟悉的圈子 |
| 8 `modes` | 哪些创作动作你愿意反复做？ | 最多三种制作动作 |
| 9 `takeaway` | 看完你的内容，你更希望观众留下什么？ | 记住人、带走结论或两者兼有 |
| 10 `signature` | 你愿意在每期内容里重复出现的一个元素是什么？ | 自愿反复出现的表达元素 |
| 11 `adjectives` | 观众用三个形容词形容你的账号，你最希望是哪三个？ | 本人的表达期待，不是观众调查 |
| 12 `mischief` | 为了节目效果，你愿意“不正经”到什么程度？ | `m0`—`m3` 的当前节目效果选择 |
| 13 `audience` | 你想让谁在什么时刻遇见这类内容？ | 具体的人与使用/观看场景 |
| 14 `value` | 用一句话补完：“看完这条内容，观众得到了____。” | 一个具体的观众结果 |
| 15 `stance` | 你更想做哪一种创作者？ | 做出东西、挑开问题或按题材混合 |
| 16 `relation` | 你希望观众把你当什么人？ | 讲解者、懂行的朋友、同好、问题解决者或未决定 |
| 17 `capacity` | 你现在能稳定投入的条件是什么？ | 每周时间、露脸/声音意愿、资源 |
| 18 `boundaries` | 有哪些边界不该为了流量被越过？ | 不能作为增长代价的事项 |
| 19 `shelf` | 一条内容发布三个月后被陌生人翻出来，你希望它怎样？ | 耐久、追当下或按栏目兼做 |
| 20 `test` | 接下来两周，什么是最小的真实试作？ | 能取得新证据的低成本作品与核验对象 |

答案可跳过。问法可以自然化，但不能改变题目要取得的信息。网站档案页只从 `creator-interview.js` 读取题目材料；协作工具读取 `skills/creator-profile/SKILL.md` 并按用户提供的材料工作。发生题目变化时，应同步更新题库与本文件，并确认网站仍展示理由和示例。

### A. 动机与回报

- `goals`：创作回报，最多选两项：表达、娱乐/共鸣、帮助、关系/参与、影响、收入/职业机会、探索。
- `success`：本人怎样判断“做成了”。
- `persistence`：连续半年数据平平时，继续创作的支撑。

逐项追问所选目标的实际含义。若目标冲突，询问本人当前愿意承担的代价；不要擅自把收入或流量设为总目标。

### B. 供给与领地

- `interests`：主动关注、观察、研究或实践的对象。
- `episode`：最近一次真实投入的事件，记录做了什么、何时、多久、为什么。
- `evidence`：作品/项目、反复求助、付费/机会、长期练习、暂无线索；可补充具体例子。
- `monopoly`：职业、经历、兴趣交叉处的内部视角，或已熟悉的圈子及其行话、争论和槽点。

兴趣没有具体行动时，只记录为兴趣线索。能力没有外部证据时，记录为“目前没有明确外部证据”，再询问愿意做的低成本试作，不判为无能力。

### C. 表达与风格

- `modes`：愿意反复做的动作：研究、解释、演示、讲故事、表演、采访、观察、组织。
- `takeaway`：观众记住创作者、带走结论或两者兼有。
- `signature`：愿意反复出现的元素。
- `adjectives`：本人希望观众使用的三个形容词。
- `mischief`：节目效果强度 `m0` 至 `m3`；这是当前选择，不是性格标签。

把“喜欢某题材”和“愿意反复完成某种制作动作”分开记录。形容词是期待，不是现有观众认知事实。

### D. 观众与关系

- `audience`：一个具体的人、遇到的时刻、需要或欲望。
- `value`：作品结束时此人得到什么。
- `stance`：建设、挑开讨论、按题材混合。
- `relation`：讲解者、懂行的朋友、同好、问题解决者或未决定。

“所有人”“普通人”“年轻人”等过宽描述需要缩到可理解的任务与场景。不要把具体观众例子自动扩大成市场规模。

### E. 节奏与约束

- `capacity`：每周时间、露脸/声音意愿、现有设备/技能/场地/素材/协作者。
- `boundaries`：隐私、商业、伦理、身体、时间与安全边界。
- `shelf`：偏耐久、追当下或按栏目兼做。
- 若填写了 `boundaries`，`tradeoff` 追问当前最愿意承担的代价。

约束应转化为方案过滤条件，不应用来评价创作者够不够努力。若用户不愿展开边界，记录未知或跳过。

### F. 验证

- `test`：未来两周可能完成的最小真实作品/片段，它要检验什么，以及向谁确认。

试作可以是脚本、演示、采访、内部试片，不要求承诺公开发布。必须把试作与它能回答的问题配对；不能用一条试作证明稳定能力或市场潜力。

## 5. 规则追问：按触发条件行动

只有当补问可能减少当前决策所需的不确定性时才触发。规则阈值是题库实现细节，不代表语义理解。

- `interests` 空白、过短，或包含宽泛词时：追问最近一次主动投入的时间与动作。
- `evidence` 选择 `none`：询问愿意做什么小作品或帮谁处理什么问题，以便观察能力线索。
- `monopoly` 空白、很短或表示想不到：改问“你是哪个圈子的自己人”，引出行话、争论和内部视角。
- `value` 空白、很短或明确写不出：回到 `audience` 所说的具体人，询问他会拿作品做什么。
- `audience` 含“所有人/大家/普通人/年轻人/女性/男性/用户”等宽泛词：要求先选一个真实或有材料观察的人和场景。
- `boundaries` 有回答：追加 `tradeoff` 当前取舍题。
- `goals`：最多选择两项后，仅对已选目标按对应题库配置追问其具体含义；不让自由文本模型自行扩展字段。

题库给出的 follow-up 最多逐条执行一次。创作者可跳过；跳过后的字段留空并进入未知项，不在后续轮次换措辞反复追问。任何隐私不适或明显不愿继续都优先于规则触发。

## 6. 自由回答抽取协议

当外部 Agent 读取访谈对话时，先保留原话，再结构化抽取。每条抽取记录至少含：

```yaml
field_id: interests
value: "创作者确认后的简洁字段值"
raw_quote: "相关原话；尽量只截取支持此字段的句子"
state: M
source_turn: 4
creator_confirmed: false
agent_inference: null
uncertainty: "是否能连续制作尚未判断"
```

- 一段回答可以含多个字段；分拆时保存同一 `source_turn`，不得丢失语境。
- 无法确定字段时，将原话暂存在 `unclassified_notes`，向创作者确认后再归档。
- 用户纠正 Agent 时，以纠正后的字段值为准，并保留旧版本为被撤回值，不争辩、不悄悄覆盖。
- 选项题仅在语义明确对应某个已存在选项时映射到选项 ID；否则放入补充文本并标记需确认。
- 对“我可以做 X”的回答记录为自述；除非有具体作品或外部反馈，不升级为能力证据。
- Agent 提出的模式解释统一标 `I`，需附相关字段；涉及将来效果的判断标 `H`。

## 7. 结构化输出

在创作者确认前，标题应为“创作者档案草案”，不可写成确定定位。输出顺序如下：

1. **版本与确认状态**：档案版本、日期、本人是否确认、最近更新时间。
2. **创作目标与取舍**：原始目标标签 + 本人描述 + 当前冲突。
3. **兴趣与稳定供给线索**：题材、最近事件、可重复动作、反例。
4. **能力与证据**：逐项注明自述、具体作品/事件、外部信号及尚未证明的部分。
5. **表达与观众假设**：动作偏好、期望风格、具体观众场景、暂定价值承诺。
6. **生产条件与边界**：时间、资源、露脸/声音意愿、不可交换条件。
7. **候选推断**：最多三条；每条含依据字段、相反证据、置信说明和待核问题。不出总分或排序。
8. **未知项与缺失字段**：明确列出；不要用通用经验填空。
9. **最小试作**：创作者自己选择的作品、观察对象、要检验的问题、成功/失败都可观察的信号。
10. **本人确认**：保留“改正 / 不同意 / 暂不判断 / 确认”的逐项入口或明确文字。

档案中所有假设与推断都应逐条追溯到访谈字段或明确外部材料。Agent 输出后再次要求创作者确认；确认前不得把候选推断交给后续 Agent 当作事实。

## 8. 更新与版本控制

- 首次生成 `v0` 草案；创作者确认后生成一个已确认版本。
- 新作品或新条件只更新受到该证据影响的字段。保留旧值、更新日期、变更原因与新证据入口。
- 目标变化由创作者陈述；环境变化由可核实事实支持；Agent 不能仅凭行为变化宣称目标已经改变。
- 发现两条材料矛盾时并列记录：两者的时间、情境、证据状态和差异。不要平均或替用户消解矛盾。
- 候选推断失效时撤回其结论，并记下是哪项观察导致撤回；不删除曾经作出该判断的来源记录。
- 保存位置和数据流由实际宿主决定。未经创作者明确知情与授权，不把答卷转送给第三方模型或存入长期记忆。

## 9. 完成与停止条件

当以下条件都满足，交付草案并停止追问：

- 已知道本人当前最重要的创作回报，或明确将其留作未知。
- 至少一个兴趣线索被放回实际事件，或明确缺少事件材料。
- 能力陈述与支持它的证据类型分开记录。
- 观众描述有具体场景，或已说明为什么仍然宽泛。
- 时间/资源约束与边界不会在后续建议中被忽略。
- 至少提出一个可由创作者选择的低成本试作；若本人不愿试作，记录其决定。
- 所有 Agent 推断、待核验判断和未知项都清楚标出。

若下一条追问不会改变候选方向、制作方式、成本预算、风险或验证设计，停止提问。不要为了填满档案表而继续访谈。

## 10. 质量核对

交付前逐项核对：

- 原话是否仍可找回？
- 有没有把本人愿望写成已发生事实？
- 有没有从一次事件泛化出稳定能力或人格？
- 有没有把观众例子升级成市场规模？
- 推断是否注明依赖哪些字段、有哪些反例？
- 创作者能否逐条修正，并能拒绝 Agent 的解释？
- 最小试作是否真的能回答所列问题？
- 未知项是否明列，而非被流畅文案遮盖？

不通过时，回退到档案草案修订；不要用更自信的语气掩盖证据缺口。
