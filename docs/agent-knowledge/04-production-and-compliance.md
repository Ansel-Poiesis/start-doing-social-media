# 制作与发布：Agent 工作协议

适用的 `article_id`：`production`、`production-brief`、`compliance`、`compliance-diff`。正式制作先读取已由创作者确认的方向与选题；内部试作可围绕待确认候选进行，但必须标出试作范围和未决项，不把制作交接当作方向自动生效。不重开已确认的方向决定，除非出现新证据或实际风险。

修订日期：2026-09-27。方法依据来自 `content.js`、`content-guides.js` 与 `content-direction.js` 的对应文章。平台规则、标识要求和法律条款变化较快；每次发布决策都需核对当前原文，本文件不是合规意见。

## `production`：选择载体与制作方式

按观众任务、承诺、证据结构与创作者资源选择图文、口播、演示、访谈、故事或混合载体。先问“观众要看见/听懂/感受什么”，再选媒介；不能因为平台热门形态就默认采用。区分必须展示的证据与装饰素材，估算脚本、拍摄/录屏、剪辑、校对和合规所需时间。若核心论点只能靠没拿到的素材成立，删减论点或等待素材，不用旁白掩盖缺口。

交付一个可比较的载体方案：观众任务、承诺、选择理由、证据对应的呈现方式、预算工时、风险与替代形式。制作方案由创作者确认。

## `production-brief`：填写制作单

逐字段生成，不得把空项自动补全为事实：

1. **观众与观看承诺：**具体的人、场景、看完可获得的结果；用目标观众语言复述检查。
2. **内容结构：**每段承担的叙事/说明功能；证据出现在哪一段；结尾与开头承诺闭合。
3. **画面清单：**人物、场景、道具、录屏、细节和转场；素材现状、缺失和替代方案。
4. **事实与来源：**逐个主张关联原始出处、日期、适用范围；意见、推断、演示结果明确区分。
5. **声音与视觉：**口播/环境声/字幕/图表的用途、来源和版权状态；避免无功能装饰。
6. **制作现实：**人员、设备、时长、预算、隐私授权、不可复现条件。
7. **成片验收：**承诺是否兑现、关键事实可核、实际阅读或完整原速播放时画面/声音/字幕是否可懂、开始与结尾是否完整。技术文件检查、内容审阅、本人签收、发布授权和实际发布回执分别记录，不能彼此替代。

**输出：**可执行制作单 + 未决素材清单 + 创作者需要确认的具体事项。当前没有足够依据时标出缺口、负责人和下一项取证；本人经历由本人提供，公开来源或已有素材可由获授权的协作者核查，不把所有缺口默认交回创作者，也不补造事实。

## `compliance`：发布前硬闸门

先确定发布平台、账号类型、内容类别、商业关系、素材来源和发布时间。逐项核对 AI 标识、广告/测评披露、资质、音乐/影像/肖像/隐私授权、站外导流、矩阵转载和平台专属要求。规则会变化；对决定发布有影响的条款必须回到官方原文确认生效日期、适用对象、地区和例外。已确认不符合的条目标 blocked；无法确认适用性或来源的条目标 unknown 并列核验动作；明确不适用的条目标 not-applicable。关键项为 blocked 或 unknown 时不标记可发布，不以模型信心代替法律或平台核查。

高风险或资质不足时建议停发、删减主张或交专业人士核验。发布决策和必要授权由创作者本人确认；免责声明不能代替适用资格、事实或权利要求。本协议只提供检查与交接，不替签；实际发布由另行获得授权的工具或人员执行。

## `compliance-diff`：比较平台差异

先逐平台引用当前官方规则，再填 AI 治理、站外导流、商业标识/测评、矩阵/首发、处罚与申诉字段。相同术语在不同平台可能有不同定义，不可横向照搬。对每项写核验日期和具体素材位置；同一作品多平台发布时生成各平台变体清单，不把“主平台通过”推成“所有平台通过”。

## 发布交接

发布前回传：作品文件/版本、平台目标、逐条来源与授权、硬闸门结果、待确认事项。已确认阻断和待核项分别保留，直到有可复核的新来源、记录或授权支持变更。证据可由获授权的协作者取得；需要专业判断或本人选择的部分仍交相应责任人确认。审核完成只证明交接状态，发布仍须实际回执。
