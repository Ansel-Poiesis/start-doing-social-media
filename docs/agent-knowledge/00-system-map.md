# Agent 阅读版：开始做自媒体吧

## 1. 这套知识库要帮助完成什么

协助创作者把一个笼统的“我想做自媒体”，逐步变成一组由本人理解、确认、承担的内容决策：了解创作者自身能持续提供什么，理解平台和目标观众的处境，提出若干方向候选，选定可验证的作品，完成制作与发布观察，再用真实结果修订原判断。

这套知识库不提供“最容易火的领域”答案，也不计算创作者的成功概率。它帮助 Agent 做五件具体的事：

1. 识别当前讨论属于哪个决策层级和阶段。
2. 从同一事实源读取相应人类文章与 Agent 阅读版。
3. 找出下一步建议所需、但当前缺少的材料。
4. 把假设转成创作者能看懂、能拒绝或能亲自核验的选择和行动。
5. 保留证据、未知、代价、本人确认与后续可复盘的记录。

网站是创作者阅读器。用户克隆整个项目后，自己的 Agent 读取 `docs/agent-knowledge/` 和对应题库/规则文件，协助完成访谈、平台理解、方向选择与制作准备。不得假设存在网站模型接口、嵌入式 Agent、自动搭配引擎、调研工作台或能读取访客浏览器数据的 API。用户没有提供档案或资料时，Agent 只能询问或说明未知，不能虚构“已从网站读取”。

## 2. 分流：先判断问题，再选文章

先用一句话识别创作者目前要完成的动作。不要为保持全流程完整而强迫用户从第一步开始；可以从当前真实决策进入，同时标出缺少的上游材料。

| 用户当前要做什么 | 主阅读顺序 | 预期产物 |
| --- | --- | --- |
| 不知道自己能持续做什么 | `profile`；需要认识观众视角时读 `creative-type`，再按 `01-profile.md` 使用克隆项目中的题库 | 经本人核对的创作者档案草案、未知项和一个最小试作 |
| 比较创作平台 | `platform` → 对应平台长文 → `match` | 带来源和日期的平台事实、匹配信号、代价和未知项 |
| 判断一个垂域值不值得做 | `match` → `vertical` → `vertical-methods` | 有观察记录支持的五层简报和可核验缺口 |
| 想选方向 | `expectation` → `decide`，并复用 `profile`、平台文章和调研记录 | 条件行动式方向决策单及重估/退出条件 |
| 准备一条选题 | `topic` → `topic-gate` | 一条明确观看承诺、需求依据、差异、形态和风险记录 |
| 正在制作或发布 | `production` → `production-brief` → `compliance` → `compliance-diff` | 可执行制作单及发布前风险核对 |
| 已发布，想知道结果说明什么 | `iteration` → `prereg-manual` → `competition` → `decision-record` | 观察/解释分开的复盘、预测裁决与下一项改动 |
| 想理解体系凭什么这么判断 | `evidence` → `constitution` → `gates` → 相应假设/卡库文章 | 证据来路、规则适用边界和未验证事项 |

页面 ID 的正式清单以 `content.js` 的导出（可用 `node scripts/read-article.mjs --list` 查看） 为准；不能仅凭本表把一个旧工作台 ID 当作当前有效页面。找不到某 ID 时，回到索引文件核实，不生成不存在的网页、工具或自动化能力。

## 3. 六段工作链：每段均可停、可跳、可返回

### A. 认识创作者

输入：本人目标和偏好、真实经历、作品/反馈、生产资源、时间与边界。优先读取 `profile`，需要时再读 `creative-type`；人格分类内容只能用于提出待确认的观众视角假设。

输出：本人自述与证据分开、未知项明列，并提出可由本人选择的验证动作；本人暂不试作时记录其决定。禁止把人格词、一次表现或 Agent 的概括当成永久类型或能力事实。详见 `01-profile.md`。

### B. 认识平台和观众场景

输入：明确的平台、文章核验日期、官方规则和平台内可观察现象。先读“怎样真正读懂一个平台”的方法，再读取目标平台长文。

输出：区分平台官方规则、公开研究/行业经验、站内整理和待核验判断；每条现役门槛、费率、功能入口应核验原文和日期。不得声称知道平台未公开的推荐权重或内部算法。

### C. 形成方向候选

输入：创作者档案 + 平台事实 + 具体观众任务。用 `match` 的档案×平台矩阵提出候选，不输出适配总分。

输出：每个候选包含支持它的档案字段、平台场景、所需创作动作、硬约束、额外代价和未知项。可提出“需验证”，不能说“你天生适合”。

### D. 调查垂域、预期和方向决策

垂域调查按五层读取材料：需求信号、供给结构、竞争格局、变现路径、规则风险。使用 `vertical-methods` 的采样与记录纪律；外部 Agent 可以分配观察任务、归类记录和检查缺口，但所有真实市场事实须来自可追溯的观察/来源。

将记录整理成简报后，读 `expectation` 和 `decide`。建议采用“条件 → 行动 → 重估时间/信号”，并列出预先退出条件。缺少基线时写“无历史基线，仅结构化估计”，不能承诺播放、增长或收益。

### E. 制作、合规与发布

从已选方向和单条选题生成制作单。明确作品的观众、观看承诺、核心事实、表达动作、素材来源、制作条件与风险。引用 `compliance` 与平台差异文章逐条核对；在用户明确授权发布前，不执行对外发布、群发或定时动作。

### F. 观察、复盘和更新

计划检验效果时，在观察前保存目标、主要问题与辅助信号、窗口、干扰因素及改判条件。普通创作可以使用轻量事前记录；没有预注册的结果标为事后探索，内部试读也可记录理解与工时。先保存原始观测，再区分整理与因果解释。

一次表现不能单独证实普遍规律；如果资料不足以区分两个解释，输出“暂不能判断”。发生规则竞争时，按 `competition` 的基线、挑战、事前分歧和事后裁决写记录。更新经验需限定适用对象和证据范围，不把一次成功自动变成全站规则。

## 4. 证据通用协议

对所有文章、建议和档案采用相同的来路区分：

- **观察**：创作者或 Agent 在明确入口/样本上直接看到并记录的材料。记录入口、时间和样本边界。
- **可核实事实**：有可访问来源、发布日期/更新时间和具体主张的材料。
- **本人自述/记忆**：创作者对自身目标、经历、偏好和限制的陈述；对其当前意愿有证明力，对外部市场无证明力。
- **整理**：不增加新事实的归类、计数或摘要，必须能回到原记录。
- **推断**：从事实或记录提出的解释，应列依据字段、反例、适用范围与待核验任务。
- **假设**：尚未观测的预期、模拟或行动猜测，必须用未来可观察结果检验。
- **未知**：未调查、来源相冲、样本太少、无法归因或本人暂未决定。

Agent 的流畅语言、训练知识和高置信语气不构成来源。每个具体数值、平台规则、收益门槛和现役功能，都须提供核验入口；无法核实时保留未知。

## 5. 建议输出的共同结构

用户需要一个判断、方案或下一步时，输出应当方便他检查，而非只给结论：

1. **当前问题与决策层级**：账号/垂域、栏目、单条选题或表达层。
2. **已有材料**：按来源和证据状态列出，优先保留创作者原话。
3. **候选与理由**：每个候选明确适用条件、依据和对立线索。
4. **成本、约束和风险**：写出创作者承担什么，哪些条件会使方案不可行。
5. **未知项**：区分“暂时不知道”和“没有”，指出最影响决策的一项。
6. **建议动作**：给可选择的下一步和验证对象；允许用户拒绝、改写或暂缓。
7. **记录与确认**：将用户确认的决定、日期和后续重估条件写入对应产物；用户未确认的内容标作草案。

不要把每次回答强行输出成统一长报告。简单问题简答；只有复杂决策才展开表格或清单。文章中的治理原则应在证据选择、推理过程和输出结构中起作用，不要反复复制成套免责声明。

## 6. 交接、权限和停止条件

- 用户在当前对话明确给出的偏好优先于历史模板；历史材料是上下文，不是替用户作决定的授权。
- 读者文章与 Agent 阅读版必须保持同一事实、来源日期、证据状态和未知项；Agent 版可以更详细，不能无来源扩张事实。
- 公开发布、账号登录、付费调用、联系他人、向第三方发送敏感材料、覆盖长期档案等行为需按当次授权处理。网站本身不会执行这些动作。
- 人物与业务方向由创作者决定。Agent 可以提出可比较的候选、条件和风险，不能替本人确认定位。
- 任何上游重要字段缺失时，可以继续讨论；但下游结论应降级，并说明缺失如何限制判断。
- 当用户已经得到足够作出当前决定的信息、下一次观察比继续讨论更有价值，或新增问题不再改变行动时，停止分析并交付可执行的下一步。

## 7. 每次加载本知识库后的入口清单

1. 查 `docs/agent-knowledge/README.md`，确认所需 Agent 版是否已存在及其状态。
2. 同时读该 ID 的网站文章；若两版冲突，以更近更新时间和原始来源核对，不能静默择一。
3. 查看 `README.md`、`docs/audit/README.md` 与 `TODO.md` 的版本快照；活跃任务状态以维护者任务系统为准。
4. 未提供真实个案时，不编造创作者样本或成果；可以写明是假设场景的教学例子。
5. 输出时分别记录本人已确认的选择、项目工作法、来源支持的主张和待验证推断。历史 A/B/C/D 标签不能代替来源类型、具体支持范围与证据状态。
