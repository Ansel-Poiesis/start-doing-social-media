# 平台与方向：Agent 工作协议

适用的 `article_id`：`creative-type`、七个平台文章、`cross-mech`、`platform-contract`、`match`、`direction`、`vertical`、`vertical-methods`、`expectation`、`decide`、`topic`、`topic-gate`、`gates`。

修订日期：2026-09-27。方法依据来自对应的人类阅读文章，尤其是 `content.js`、`content-direction.js` 与 `content-plat-a/b/c.js`。平台现行规则仍以原始官方来源为准；本协议不复制会过期的门槛和数字。

网站文章解释概念并让创作者作判断；本文件规定 Agent 如何读取材料、组织证据、提出可检查的候选。进入任何任务前先读 `00-system-map.md`；需要具体创作者材料时读 `01-profile.md`；讨论平台事实时同时读 `02-platform-reading.md` 与对应平台人类文章。不要把 Agent 阅读材料当作平台事实的替代来源。

## 通用协议

1. 明确当前要帮助创作者作出的一个决定，以及决定期限。资料收集不得脱离这个决定无限扩张。
2. 读取创作者已确认的档案版本、候选方向和资源约束。将原话、可核证据、创作者解释、Agent 推断分别标记；缺失字段保持未知。
3. 平台信息先回到文章中的原始来源与核验日期。变化中的功能、门槛、处罚、收入和产品入口必须重新查官方原文；无浏览或登录权限时明确说不能核验，并给出人工核验任务。
4. 提议必须带依据、反例或未知、代价、下一项低成本验证。不得输出“最适合”“成功率”或伪精确总分。
5. 方向由创作者决定。只有创作者确认的方向进入制作；Agent 不能替签、替发布或把暂定候选写成长期身份。

## 按文章 ID 执行

### `creative-type`：创作型人格参考

- **触发：**创作者希望借分类词汇描述内容给人的感觉，或理解表达偏好。
- **读取与判断：**先按 A 动机与回报、B 供给与领地、C 表达与风格、D 观众与关系、E 节奏与约束整理档案。自述、作品证据、条件、反例/未知和本人确认分栏；资源限制不能误写成稳定人格。访谈与证据梳理后，才将 VCTI、品牌原型、Aaker 词汇作为观众视角的参照镜。镜子矛盾时保留矛盾。
- **输出：**五维画像（偏好/重复行为、证据、成立条件、反例/未知、确认状态、关联决策）+ 可选的观众视角假设卡。若提出候选分类，描述可观察模式、反例和适用边界；不发固定类型结论，不打总分。
- **停止：**不做心理人格诊断；候选分类未有重复样本和试作依据时标记“暂定”，不得用 VCTI、品牌原型或自述分数替代本项目分类，也不能用分类替代平台调查或方向试作。

### 平台文章：`xhs`、`douyin`、`wechat`、`bilibili`、`zhihu`、`toutiao`、`baijiahao`

共同任务是把平台文章变成“这项选择会带来什么条件”的证据卡，而非背诵结论。每篇单独输出：产品/观众处境、发现入口、内容形态、观看后动作、创作者可见指标、变现入口、合规边界、资料日期和未知项。对影响当前决策的门槛与规则，逐条打开原始来源核验其适用对象和更新时间。

| `article_id` | Agent 特别核对的决策材料 |
| --- | --- |
| `xhs` | 搜索与推荐入口是否适合候选题；图文/视频及首图承诺；社区治理、商业报备、站外导流边界；报价行情必须标清样本与日期。 |
| `douyin` | 推荐、搜索和直播是不同场景；区分官方算法说明与“流量池”传说；商业合作、直播锚点、信用分及私信限制逐项核对。 |
| `wechat` | 公众号、视频号、小店等不是同一分发面；核对订阅、搜索、推荐、首发排期和组织账号条件，勿把生态内一个入口外推到全生态。 |
| `bilibili` | 区分播放、完播、硬币、弹幕和关注各自能说明什么；核验投稿/社区规范、花火与收益门槛；长视频工时须进产能估计。 |
| `zhihu` | 分清问题页排序与推荐流；引用投票、盐值、折叠和复活规则时核对当前定义；把评论争议和内容可信度纳入成本。 |
| `toutiao` | 核对分成公式、成长权益、首发与排期的生效条件；历史算法文章只能解释历史机制，不可当成当前公式。 |
| `baijiahao` | 先确认账号入口、产品迁移和收益资格仍有效；分清百度搜索、信息流推荐及第三方收益样本；高风险垂类须核资质。 |

不要给平台打“优劣分”。若来源相互冲突，保存原文、日期、适用条件和冲突点，结论降为未决；把冲突转成创作者能执行的核验项。

### `cross-mech`：跨平台机制共性

先把每条共性拆成“适用平台、共同事实、例外、来源”。分别标记哪些是多源共证、哪些只是类似现象。不能将一个平台的个案推广到七个平台，也不能从同时出现的互动指标推断推荐因果。输出仅用于提出待比较的机制假设。

### `platform-contract`：平台长文写作契约

Agent 起草、更新或审读平台长文时，检查是否按统一栏目覆盖：平台/观众画像、发现与分发、内容时间线、创作者可见信号、规则与治理、变现、实作清单、来源及未决项。所有作为事实引用的数字都需给出处、日期、适用范围、来源类型与支持状态；对照上版标出新增、更正、失效，不默默覆盖。缺少官方证据时保留空缺，不拿经验帖补成平台规则。

### `match`：档案×平台搭配方案

- **输入：**创作者确认过的档案、平台事实记录、当前资源与不可接受成本。
- **流程：**先列硬约束与红线；再为每条候选写“档案信号 × 平台结构 × 内容形态”的相遇点；随后写代价和反证。形成 2–4 个可比较候选，不加权求总分。
- **输出：**候选矩阵，逐行给出支持证据、未知、代价、可检验的小试作、淘汰/保留理由。站内矩阵标注待验证推断，单独记录所依赖的平台事实和证据缺口；历史 D 级标签不能当可信度结论，也不能当市场验证。
- **停止：**档案关键字段缺失、平台事实过期、或硬约束不清时，不排顺序，只提出补证问题。

### `direction`：把两份档案交叉成方向

围绕一个具体观众场景，把“创作者能持续供给什么”与“平台上的人正在做什么”逐条相连。每个方向必须有承诺句、证据链、差异轴、最低试作和失败时的信息价值。优先用短周期作品检验最大的未知；不要从兴趣直接跳到垂域结论。

### `vertical` 与 `vertical-methods`：定义垂域并调查

把宽主题切成可搜索、可抽样、可比较的“人群 × 场景 × 任务/情绪 × 内容承诺”。每次调查先固定平台、产品入口、地区/语言、账号条件、关键词、日期、样本规则和预算。五层记录分开保存：需求信号、供给结构、对标账号、变现路径、规则与风险。

每条记录包含唯一 ID、观察对象、原文/链接或截图出处、日期、方法、可观察事实、解释、反例、置信边界和层级。评论区重复提问是需求线索，不等于市场规模；账号收入截图不能证明普遍变现；无法访问的后台数据写不可得。跨源验证要说明来源是否独立，不能把同源转述算成多票。

**交付：**可复查的原始记录、分层摘要、竞争差异轴、变现/资质待核项、未决问题与下一次采样。不得把样本描述升格成全平台比例或因果结论。

### `expectation`：由调研形成预期与建议

先对观众线索、供给条件和实际风险逐项记录支持材料、冲突或证据不足；收入是本人目标时再核变现，否则标不适用。证据不足时不作肯定市场建议，但仍可为不公开的理解检查、草图或供给试验建立预期。按拟进行的动作记录时间、成本和回报三条线：何时观察什么、投入多少、可见行为能支持和不能支持什么、何种结果触发重估；不把互动指标与心理动机一一对应。

交付“进入 / 调整 / 放弃”三类条件建议；同步写退出条件和重估日期。没有账号历史数据时标注“无历史基线，仅结构化估计”，不承诺增长、收入或爆款日期。

### `decide`：确定方向与规划选题

把 2–4 个候选及其证据、代价、未知和退出条件交给创作者。创作者确认后记录主方向句、依据链、差异轴、放弃项、预期、重估日期和确认日期。随后按重复抱怨、创作者交叉经验、差异轴、官方选题信号等来源建选题池；首批内容同时检验观看承诺、供给成本与目标观众理解。没有本人确认不得将决策单标为生效。

### `topic` 与 `topic-gate`：从方向到单条作品

先说清本轮要验证的变量，再比较候选。对每题分别写：观众意图/观看承诺、需求证据、差异轴、载体匹配、风险和退出方式。不得汇总成“爆款评分”。测试结果应能区分候选之间的预测；若所有候选都依赖同一未经验证的假设，先设计辨别性更强的试作。

**正式制作与发布前的必要检查：**承诺可复述、关键主张有材料兑现、形态与资源匹配、适用的法律/平台要求和本人边界已处理。缺项须标明影响和下一动作，不得冒充通过。为获取缺失证据而进行的内部草图、理解检查或小试作，可以在已授权且实际风险可控的范围内继续；记录它尚不能支持的结论，不因此标记方向已确认或作品可发布。

### `gates`：栏目、选题、表达三级门禁

严格分开三种裁决：栏目判断长期供给是否成立；选题判断本条是否值得制作；表达判断标题、措辞或首图是否清楚且合规。使用文章定义的裁决词汇记录通过、限域、返工或退役。局部表达可改不代表栏目已成立；单条数据好也不自动通过栏目门。

## 共同交付格式

```text
当前决策：
创作者确认过的输入版本：
证据记录 ID 与来源日期：
观察 / 他人反馈 / 创作者解释 / Agent 推断：
候选与代价：
反例及未决项：
建议动作与通过条件：
最小验证及需要创作者确认的事项：
停止或重估触发器：
```
